County records lead pipeline: Lis Pendens & probate filings matched to property data

Data Engineer | Public Records Scraping & Document AI

A real estate investment team was copying new foreclosure and probate filings from county websites by hand every morning. I built a pipeline that collects them from five county clerk sites, reads each recorded document with OCR and AI, matches the property on the county appraiser site and delivers scored leads before the team starts work.

The challenge

The team buys properties from owners facing foreclosure or settling an estate. Every morning, two assistants searched five county clerk websites for new Lis Pendens and probate filings, opened each scanned document, copied the property details and then looked up the owner on the property appraiser site. It took about five hours a day, leads were often a day late, and the same property was sometimes entered twice.

The solution

Each county site got its own small adapter, because every county uses different search software. A scheduled run searches yesterday’s filings, downloads the recorded documents, reads them with OCR and uses AI to pull out the case details and the parcel ID or property address. The parcel is then looked up on the county property appraiser site for the owner, mailing address and value. Leads are deduplicated, scored and delivered to a Google Sheet and the team’s CRM before 7 a.m., each with a link to the original document.

How it works

  1. Search new filings by dateEach county adapter searches the official records site for yesterday’s recordings of the chosen document types (Lis Pendens, probate petitions, letters of administration).
  2. Handle each portal’s quirksDisclaimer pages, session tokens, paging and occasional CAPTCHAs are handled per county. Settings for each county live in one YAML file.
  3. Download the recorded documentMulti-page TIFF or PDF images are saved to an S3 archive with the instrument number as the file name.
  4. Read the document with OCRPages are cleaned up with OpenCV and read with Tesseract. Stamps, faint scans and two-column layouts are handled.
  5. Pull out the key fields with AIThe OpenAI API turns the OCR text into a fixed JSON schema: case number, plaintiff, defendants, property address, legal description, parcel ID and recording date.
  6. Match the propertyThe parcel ID (or the address, with fuzzy matching) is looked up on the county property appraiser site for owner, mailing address, market value, last sale and homestead status.
  7. Score and deliverAbsentee owner, estimated equity, homestead and filing type give a 0 to 100 score. New leads are pushed to Google Sheets and the CRM, and Slack alerts the team if a county returns zero rows or its site changes.

Technical challenges and how they were solved

  • Five counties, five different websites: one adapter per county behind a shared interface, so a site change only touches one file
  • Documents are images, not text: OCR with image cleanup, then AI extraction that copes with OCR errors
  • Parcel IDs missing from some documents: address and legal description matched against appraiser data with fuzzy matching
  • The same property filed in more than one record: deduplication on parcel ID and normalised address across 90 days
  • Sites that change without notice: daily checks that alert on zero results or missing fields

Responsible use

  • Only public court and property records, the same data anyone can view on the county sites
  • Low request rates during off-peak hours, following each site’s terms of use
  • Original documents are kept so every lead can be checked against its source

Results

  • About 200 new filings a day collected, read and matched in 22 minutes instead of about 5 hours by hand
  • 96.7% of filings matched to a parcel automatically, the rest sent to a short review list
  • Leads ready in the CRM by 7 a.m., a full day earlier than before
  • No more duplicate entries, and every lead links back to its recorded document
