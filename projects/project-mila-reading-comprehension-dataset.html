Project Mila: large-scale reading comprehension dataset generation

AI Engineer | LLM Data Pipeline Developer

A high-throughput synthetic data pipeline that turns raw English articles into structured reading comprehension questions. Each article produces 7 multiple-choice questions across four skill categories, for a final dataset of 1.5 million Q&A pairs ready for LLM training and evaluation.

The challenge

Creating reading comprehension data by hand is slow and expensive. Naive LLM generation at scale breaks down in three ways: malformed JSON outputs, repetitive question phrasing (“What…”, “Which…”, “Why…”), and inconsistent quality across millions of generations. The pipeline had to be fast, diverse and self-healing.

The solution

I built an end-to-end pipeline that runs gpt-oss-20b on vLLM in large GPU batches, uses carefully engineered prompts for varied questions, repairs and validates every model response, retries anything that fails, and cleans and tags each record before it enters the dataset.

How it works

  1. High-throughput inferencegpt-oss-20b runs on vLLM with prefix caching and bfloat16, processing batches of 1,000 articles at once on GPU.
  2. Structured question designEach article generates 7 questions: 2 detail comprehension, 2 inference and reasoning, 2 opinion and attitude, and 1 main idea.
  3. Creative prompt engineeringPrompts ban overused starters (What, Which, How, Why) and push varied phrasing, so questions are diverse rather than templated.
  4. Multi-strategy JSON repairA 5-step recovery system fixes escaping errors, missing commas, truncated outputs and incomplete objects, salvaging responses that would otherwise be discarded.
  5. Validation layerEvery question is checked for required fields, exactly 4 options and a valid A–D answer before it enters the dataset.
  6. Automatic retry loopFailed articles are re-queued and reprocessed with a lower temperature (0.9 → 0.7) and a stricter prompt.
  7. Post-processing and enrichmentBoilerplate phrases and HTML are removed, emails and phone numbers are anonymized, options are formatted consistently, and each record is tagged with domain, education stage, question type, word count and a unique hash ID.

Key features

  • 1.5 million validated Q&A pairs
  • 7 questions per article across 4 cognitive skill categories
  • 5-strategy JSON repair engine
  • Field-level validation and answer normalization
  • Automatic retry queue with adjusted temperature and prompt
  • Anonymization of emails and phone numbers
  • Metadata: domain, education stage, question type, word count, hash ID
  • Custom error tracker with a full JSON error report
  • Checkpoints to Google Drive and GPU memory cleanup for long runs

Results

  • 1.5M validated Q&A pairs generated
  • 7 questions per article across 4 skill categories
  • Output in both JSON and CSV, with an error report for auditability
  • A self-healing pipeline that recovers malformed outputs instead of losing them
